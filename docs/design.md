## 決めたこと

- まず全16シーンを軽めの版で通しで作り、そのあとセクション(A・B・プレサビ・サビ)ごとに作り込んだ。この表は素案で、実装の内容は README の「シーン一覧」にある
- 作り込みの方針: 各シーンを、右下に表題欄のある1枚の「図面」にする。計算は見た目だけでなく実際に解く(導体球の力線、IEEE 754 のビット、共分散の固有分解、蔵本モデル、トポロジカル電荷など)。見せ場は、キーワードが来る2小節目の頭に置く
- #5 の間奏は、作者の研究(ブロッホスキルミオンの生成・分割)へのオマージュにする。急冷で迷路状のドメインができ、磁場を上げるとちぎれてスキルミオンが生まれる
- #2 のケージは「視点の周り」ではなく、ステージ全体を覆う机の上のドームにする(スマホの AR では、目の周りの球は近すぎてほとんど見えないため)
- #15 の「全シーンの要素が一斉に動く」は、#15 のシーンの中に、それまでのモチーフの縮小版を並べて動かす。同時に表示するシーンは1つ、という仕組みは変えない
- SATISFACTION の行は #14 に含める(#14 を4小節にして、後半で1つの世界だけを残す)
- #11 はポストエフェクトを使わず、描いた線を2つの像に分けて揺らす(WebXR ではポストエフェクトが扱いにくいため)
- シーンの中のタイミングは拍で書く。たいていのシーンは2小節(8拍)。#1 と #2 は1小節、#14 は4小節、#5 は間奏を含めて10小節
- #5 は「SIMULATION」で曲が盛り上がって間奏に入るので、間奏の8小節をシミュレーションの見せ場にする
- シーンの切り替えはクロスフェード(前のシーンを終わったあと 0.75 拍だけ残す)
- 床(ブループリントの台紙)は全シーン共通にして、シーンが続く間は出しっぱなしにする。各シーンは右下の表題欄に図番(#)と題名を入れ、全体を1冊の図面集のように見せる

## 曲の構成

[Demucs](https://github.com/adefossez/demucs)(htdemucs)で声を分離し、拍グリッドの小節ごとに声の量を調べた(分離は開発環境で一度だけ行い、リポジトリには入れていない)。
曲は頭からいきなり歌で始まり、「SIMULATION」のあとで曲が盛り上がって、声のない間奏に入る。
